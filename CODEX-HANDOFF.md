# Контекст для нового чата Codex

## Цель проекта

Репозиторий — форк RustDesk, брендируемый как **iRidiDesk**.

Текущий этап: довести до результата существующий **32-битный тонкий клиент** для Windows. Сборку запускает только пользователь вручную. Codex не должен запускать фоновую или самостоятельную сборку.

## Требования к тонкому клиенту

- Принимает только входящие подключения; самостоятельное подключение к другим устройствам недоступно.
- Должны работать передача файлов и текстовый чат.
- Терминал отключён.
- Сервер ID и ретранслятор: `rustdesk.iridi.cloud`.
- Server API должен оставаться пустым.
- Сетевые настройки и ключ не должны быть видимыми в интерфейсе и не должны лежать открытым текстом в исходниках или в Git.

Важно: данные подключения, вшитые в EXE, нельзя сделать абсолютно секретными — опытный пользователь может извлечь их из программы. Текущая мера защищает от случайного копирования: настройки закодированы при сборке, интерфейс настройки скрыт. Реальная защита сервера от посторонних клиентов должна обеспечиваться на стороне сервера: ACL/авторизация RustDesk Pro, VPN или сетевой firewall.

## Конфигурация сервера

Секретный ключ **не записывать** в Git, документацию, коммиты или сообщения чата. Он должен находиться только в локальном файле `.env` в корне проекта. Этот файл игнорируется Git.

Создать `.env` из `.env.example` и заполнить:

```text
IRIDI_RENDEZVOUS_SERVER=rustdesk.iridi.cloud
IRIDI_RELAY_SERVER=rustdesk.iridi.cloud
IRIDI_PUB_KEY=<секретный ключ сервера>
```

## Уже внесённые изменения

Ветка `main` содержит следующие важные коммиты:

- `221a65e` — скрытие/фиксация конфигурации тонкого клиента, отключение терминала и исходящих подключений.
- `b601a20`, `a84e665`, `8348f82`, `28d1623` — адаптация сценария сборки 32-bit на ARM64-хосте через x64-эмуляцию Windows.
- `b15e50d` — диагностический скрипт окружения сборки.

Изменения тонкого клиента находятся преимущественно в:

- `libs/hbb_common/build.rs` — создание закодированных настроек из переменных окружения сборки;
- `libs/hbb_common/src/config.rs`;
- `libs/hbb_common/src/websocket.rs`;
- `src/client.rs`, `src/common.rs`, `src/rendezvous_mediator.rs`;
- `src/ui/index.tis`.

## Сценарий релизной сборки

Главный скрипт: `scripts/build-release.ps1`.

Он собирает x86-версию с Rust toolchain `stable-x86_64-pc-windows-msvc` и целью `i686-pc-windows-msvc`, затем создаёт архив в `dist`.

На обычном 64-битном ПК с Windows 10/11 до сборки сначала запустить только диагностику:

```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\scripts\Test-BuildPrerequisites.ps1
```

Скрипт диагностики ничего не устанавливает, не изменяет и не собирает. Его полный вывод нужно прислать в чат, если есть `MISSING` или `WARNING`.

Когда диагностика полностью успешна, пользователь сам запускает релиз:

```powershell
.\scripts\build-release.ps1 -Version 1.0.2
```

Никогда не запускать эту команду самостоятельно без явного поручения пользователя.

## Зависимости, которые проверяет диагностика

- Git for Windows;
- Rustup и Cargo;
- `stable-x86_64-pc-windows-msvc`;
- Rust target `i686-pc-windows-msvc`;
- Visual Studio 2022 Build Tools с MSVC v143 C++ x64/x86;
- Windows 10/11 SDK;
- наличие локального `.env` без раскрытия его содержимого.

## Дальнейший план после 32-bit тонкого клиента

1. Протестировать собранный x86 EXE на 32-битной Windows: входящее подключение, чат, файлы, отсутствие терминала и невозможность исходящего подключения.
2. Сделать тонкий клиент на актуальной 64-битной версии RustDesk.
3. Сделать 64-битный толстый клиент для сотрудников: ребрендинг и предустановленный сервер.

## Правила работы

- Не удалять пользовательские изменения и не использовать `git reset --hard`.
- Перед отправкой изменений в GitHub показывать или кратко объяснять, что меняется; пушить только в `main`, если пользователь явно не попросил иное.
- Не печатать и не коммитить секретный ключ из `.env`.
- Не запускать сборки в фоне. Пользователь запускает их сам и присылает полный вывод.
